# T01のCSC v1が染みを黒文字にする原因

保存済みACE入力で現行v1の黒文字分類を再計算すると、全ページの保存黒マスクと全画素一致した。比較画像での反転、範囲の取り違え、保存マスクの読み間違いではない。

この例の大きな誤検出は、ACE前処理で暗くなった染みと、輝度クラスタを黒文字と対応づけるv1の設計の組み合わせが主因と考えられる。同じ黒文字分類処理で入力だけ原画像に戻すと、大きな染みの誤検出が大幅に減った。

## 処理経路

`scripts/generate_csc_masks.py` は保存済みACE画像を読み、`modules/ddrm_npj/scripts/csc.py` の `color_space_clustering` を呼ぶ。T01のv1とv2の保存入力は全画素一致し、`split_dataset_csc` のACE画像とも一致した。

v1の黒文字分類には固定の黒閾値がない。第1段階でLabのL・LuvのL・グレー値の3次元をPCA・3成分GMMに渡し、外周を除く平均Lが最小のクラスタ全体を黒文字扱いする。第2段階は劣化クラスタだけを処理し、既に黒文字へ入った染みを再判定しない。`red_a_min=133` は朱分類の閾値であり、この黒文字判定は変えない。

## 条件を一つずつ変えた確認

以前の比較で原画像から手指定した、T01の文字を含まない確認範囲 `[280,130,50,45]`（ROI相対座標）を使用。2,250画素について黒文字に分類された割合は次の通り。

| 条件 | 黒文字扱いの画素数 | 割合 |
| --- | ---: | ---: |
| 保存済みv1／同条件の再計算 | 2,250 / 2,250 | 100% |
| Lab・LuvのLを `/100` から `/255` に変更 | 2,250 / 2,250 | 100% |
| GMM初期化を1回から10回に変更 | 2,250 / 2,250 | 100% |
| 原画像入力に変更、ACEを外す | 13 / 2,250 | 0.58% |

初期化を10回にしても黒マスクは全ページで同一だった。全条件でGMMは収束していた。値域補正では全ページで2,731画素の判定が変わったが、この染みの確認範囲は変わらなかった。

OpenCVのuint8変換を実測すると、白のLab・LuvのLは255だった。既存コードの `/100` では最大2.55となるため、0〜1へ揃える正規化にはなっていない。この不整合はあるが、それだけの補正では今回の大きな誤検出を説明・解消できない。色成分のスケールを変えることはGMMの条件変更でもあるため、補正結果を原論文の忠実再現とは扱わない。

## 比較と判断

[原因切り分けのPNG](T01_CSCv1_原因切り分け.png)は原画像・ACE入力・保存v1・ACEなしv1・正規化補正・Wolfを同じ範囲で並べた。

保存v1が悪いことを、この画像だけでCSC全般の性能が低い根拠にはできない。Wolfとの同一入力による比較にはACEなしv1の対照が必要だった。原画像入力のv1でも細線の欠けや他の汚れの誤検出は別途評価が必要で、これを全ページで改善した実装と断定しない。

既存のACE画像、v1/v2マスク、パイプラインコードは変更していない。原画像入力のv1は診断用対照として別保存した。数値は限定した確認範囲の誤検出率であり、ページ全体の精度やF1ではない。

入力照合、全ページ一致、クラスタ平均L・画素数、正規化実測、条件別の確認範囲計数、ソースハッシュは `diagnostics.json` に保存した。再計算スクリプトは `../audit_csc_v1.py`。
